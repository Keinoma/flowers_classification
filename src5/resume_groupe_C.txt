# Groupe C — Fine-tuning : Résumé des particularités

## Qu'est-ce qui distingue le Groupe C des autres groupes ?

Le Groupe C est la version complète et non restreinte du transfer learning.
Contrairement au Groupe B (backbone gelé, feature extraction pure), ici
**tout le réseau apprend**, y compris les couches profondes pré-entraînées
sur ImageNet. C'est le seul groupe où les connaissances génériques
(bords, textures, formes) sont réellement adaptées au domaine spécifique
des fleurs.

## Les trois particularités clés

### 1. Dégel des poids du backbone
Dans le Groupe B, seule la tête de classification (~0,5 % des paramètres)
était entraînée. Dans le Groupe C, les ~23,5 millions de paramètres de
ResNet50 sont eux aussi mis à jour. Les filtres des premières couches
(détection de contours) comme des dernières couches (formes complexes)
vont lentement pivoter pour devenir des détecteurs de pétales, de tiges,
de textures florales spécifiques.

### 2. Learning rate différencié (subtilité essentielle)
On ne peut pas entraîner le backbone et la tête avec le même LR — sinon
on détruit les connaissances pré-entraînées en quelques batches. La
pratique standard est d'utiliser un LR 10 à 100 fois plus faible pour le
backbone (ex: 1e-5 pour ResNet50 contre 1e-3 pour la tête). Cela se fait
en passant deux groupes de paramètres distincts à l'optimiseur, chacun avec
son propre LR.

### 3. Stratégie de dégel progressif (optionnelle mais recommandée)
Plutôt que de tout dégeler d'un coup, une approche plus sûre consiste à :
- Commencer par entraîner quelques époques avec le backbone gelé (comme
  le Groupe B) pour que la tête converge
- Puis dégeler progressivement les couches hautes de ResNet50 (layer4,
  puis layer3...)
- Éventuellement tout dégeler pour les dernières époques avec un LR très
  faible

## Ce que le Groupe C va révéler

Ce groupe répond à la question ultime : les features génériques d'ImageNet
suffisent-elles, ou les fleurs nécessitent-elles des représentations
vraiment spécialisées ?

- Si C >> B : le domaine des fleurs est suffisamment différent d'ImageNet
  pour justifier l'adaptation des features. Le fine-tuning est rentable.
- Si C ≈ B : les features pré-entraînées sont déjà optimales. Le
  fine-tuning n'apporte rien (ou overfitte sur le bruit du dataset).
- Si C < B : overfitting. Le backbone a oublié ses connaissances génériques
  sans avoir assez de données pour apprendre des features florales robustes.

## Contraintes pratiques à anticiper

- Temps d'entraînement : environ 10 à 50 fois plus long que le Groupe B
  (backpropagation sur tout le réseau).
- Mémoire GPU : plus élevée car les gradients sont calculés pour toutes
  les couches.
- Risque d'overfitting : beaucoup plus de paramètres entraînables avec le
  même nombre d'images — d'où la nécessité d'un early stopping.
- Besoin de régularisation : le weight decay et le dropout de la tête
  deviennent encore plus importants.

## En résumé

Le Groupe C est le seul groupe où le modèle apprend vraiment à "voir" les
fleurs plutôt que de se contenter de classer des features génériques.
C'est aussi le plus risqué (overfitting, instabilité) et le plus coûteux
en temps de calcul. Son résultat face au Groupe B te dira si ton problème
mérite un investissement en fine-tuning ou si la feature extraction figée
suffit amplement.
